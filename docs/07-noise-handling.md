# 7. Борьба с шумом: тощий контекст для Fable 5

Сводная памятка по одной теме: **шум — это любой контекст, который модель не просила и который не меняет результат**. Для слабых моделей избыточные инструкции были страховкой; Fable 5 они *мешают* — модель следует инструкциям буквально, и каждая лишняя строка либо размывает фокус, либо провоцирует нежелательное поведение (over-delivery, overtriggering, ложные срабатывания классификаторов).

Материал собран из [03-prompting.md](03-prompting.md), [04-agents-long-running.md](04-agents-long-running.md) и [05-community-insights.md](05-community-insights.md); источники — там.

## 7.1 Три места, где живёт шум

| Где | Что это | Чем вредит |
|---|---|---|
| CLAUDE.md / системный промпт | Строки, которые модель узнала бы сама сканированием проекта | Размывание внимания; «security-подобный» текст триггерит классификатор с первого сообщения |
| Промпт задачи | Пошаговые скрипты, «act as expert», КАПС-императивы, кусочная подача контекста | Снижение качества (официально подтверждено), overtriggering, откаты при дозаявке требований |
| Вывод модели | Непрошеные фичи, рефакторинг рабочего кода, arrow-chain-стенография, разделы «альтернативы» | Расход дорогих выходных токенов ($50/M), ревью-нагрузка |

## 7.2 Шум в CLAUDE.md

Правило: **CLAUDE.md — тощий.** Fable 5 сама сканирует проект, поэтому в файле должно остаться только то, что из кода не выводится.

Оставить:
- неочевидные соглашения («миграции пишем только через `make migration`, не через ORM»);
- команды сборки/тестов/линта, если они нестандартные;
- явные запреты («не трогать `legacy/`», «не обновлять зависимости»);
- указание на память проекта, если она есть (`notes/*.md`).

Убрать:
- описание структуры каталогов и стека — модель увидит сама;
- общие наставления («пиши чистый код», «будь внимателен»);
- «CRITICAL: YOU MUST…» — вызывает overtriggering;
- security-подобные формулировки («никогда не логируй пароли», «эксплойты», «обход защиты») — по опыту Habr и Claude Code именно контекст репозитория провоцирует скрытый reroute на Opus 4.8. Если такие правила нужны, формулируйте нейтрально: «секреты — только через переменные окружения».

Диагностика: внезапная «тупость» модели в сессии = вероятный скрытый fallback на Opus 4.8. Первое, что стоит проверить, — не появился ли в CLAUDE.md или промпте кибер/хим-похожий текст.

### До / после

До (шум помечен):

```markdown
# CLAUDE.md
Ты — старший разработчик с 20-летним опытом.          <- шум: act-as-expert
Проект — REST API на FastAPI, структура:               <- шум: модель увидит сама
  src/ — код, tests/ — тесты, alembic/ — миграции
ВАЖНО!!! ВСЕГДА пиши типизированный код!               <- шум: КАПС + общее место
Никогда не создавай уязвимости и не пиши эксплойты.    <- шум + риск классификатора
Тесты: pytest -q (обёрнут в make test из-за env-переменных)
Миграции только через make migration, не через alembic напрямую.
```

После:

```markdown
# CLAUDE.md
Тесты: make test (не pytest напрямую — нужны env-переменные).
Миграции: только make migration, не alembic напрямую.
Секреты — только через переменные окружения.
```

## 7.3 Шум в промптах

- **Цель вместо скрипта.** Давайте направление, контекст, цели и критерии проверки — не перечисление шагов. После миграции со старых моделей A/B-тестируйте промпты со снятым скаффолдингом.
- **Фронтлоад.** Весь контекст, ограничения и критерий «готово» — одним первым сообщением. Кусочная подача заставляет модель оптимизировать под фрагмент и откатываться.
- **Явный effort и объём ответа.** Неопределённость модель разрешает удлинением — это тоже шум, только на выходе.
- **Причина, а не только просьба:** «I'm working on X for Y. They need Z. With that in mind: …» — понимание намерения заменяет страницу инструкций.

## 7.4 Шум на выходе

Два готовых сниппета из [03-prompting.md](03-prompting.md):

Против over-delivery:

> Don't add features, refactor, or introduce abstractions beyond what the task requires. Do the simplest thing that works well. Only validate at system boundaries.

Против плотного «телеграфного» стиля:

> Lead with the outcome. Your first sentence should answer "what happened" — the TLDR. Supporting detail after. Keep output short by being selective about what you include, not by compressing writing into fragments or arrow chains.

## 7.5 Чек-лист внедрения

1. Пройтись по CLAUDE.md: удалить всё, что модель узнает сканированием; переформулировать security-подобные строки нейтрально. Целевой размер — экран или меньше.
2. Взять один рабочий промпт, снять старый скаффолдинг (шаги, роли, КАПС) и сравнить результат с исходным.
3. Добавить в системные инструкции анти-over-delivery- и стиль-сниппеты из 7.4.
4. Переписать шаблон первого сообщения так, чтобы он вмещал весь контекст и критерий «готово» (см. [шаблон CLAUDE.md](../templates/CLAUDE.md.template)).
5. При деградации качества в сессии — сначала проверить контекст на слова-триггеры, потом всё остальное.
